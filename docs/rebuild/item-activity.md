# Item activity projection

Staff-only `GET /stock/:id/activity?size=25&cursor=...` and realtime `inventory:activity` (`{itemId,size,cursor}`) return `{items,nextCursor,isDone,historyStatus}`. Existing live-session authorization applies to both entry points; no public catalogue endpoint exposes this projection.

Each row contains `id`, `kind`, `occurredAt:number|null`, `quantityDelta:number|null`, and `{type,id}` source provenance. Optional fields: `lotId`, `reference`, `counterpartItemId`, `reversesId`. Positive quantities enter the article's stock, negative quantities leave it; zero is an explicitly recorded terms/correction event. Unknown dates and quantities remain null. `reversesId` refers to an original projection key in legacy and an original stock-operation ID in canonical; it is provenance, not a cursor or universal navigation ID.

Kinds are validated as acquisition, sale, sale-cancellation, gift, gift-reversal, opening, opening-reversal, consignment-return, consignment-terms, purchase-correction or opening-balance. Source types are validated actual record tables: items, stockItems, stockLots, stockMovements, purchases, supplierReceipts, consignments, consignmentReturns, sales, stockGifts, stockOpenings, consignmentEvents, stockOperations and auditEvents. Source IDs are not remapped to another model's ID space.

Canonical source movements produce one effect per movement/lot, preserving FIFO allocation granularity. Incomplete historical gift/opening operations additionally produce a null-quantity marker, rather than a guessed delta. Imported opening balances represent reconstructed starting stock, not a claim that all old acquisitions are known. Legacy sources include individual acquisitions, supplier lots, sales and cancellations, gifts and reversals, display openings on both affected articles and reversals, consignment returns and terms. Removed legacy purchase articles retain a correction with unknown timestamp where only removal provenance survived.

The projection is disposable and cannot determine stock, costs, payments or signatures. `convex/shared/itemActivity.ts` implements stable keys, per-source replacement, orphan pruning, indexed pagination and bounded resumable maintenance. Business mutation wrappers flush only changed source records after their handlers finish, in the same transaction. Historical imports intentionally bypass those wrappers and rebuild after all references are resolved. The maintenance API is internal only; the checked-in CLI accepts explicit loopback targets and matching private admin credentials.

Query work is bounded by the requested 50 effect rows plus session/item/index-state checks. Rebuild chunks contain at most 20 source rows with a1 MiB source-page read target and resumable cursor; ordinary legacy sources produce at most 4 effects and canonical movement rows 1 effect (incomplete operations at most 2 markers). Legacy large-purchase validation uses 50-item scheduled repair chunks and exposes indexing until drained. No global ledger scan occurs in the item query. Source creation itself still obeys existing business transaction limits; this projection does not remove Convex's finite write/read budgets.

Validation: dedicated legacy/canonical tests exercise exact signs, sale cancellation replay, gift/opening reversals, pagination without duplicates, authentication, unknown historical cancellation dates, source replacement/deletion, rerun stability, unchanged financial sources and large-purchase repair. Final local3220 rebuild completed 701 processed records and isolated3224 completed 385, both followed by an unchanged completed resume; local3210 completed 95 at its initial verification; these counts are checkpoint-specific, not business totals.


Purchase date corrections preserve stockOperation/movement timestamps and quantities. The acquisition effect displays the current lot.acquiredAt, matching the corrected purchase and legacy display semantics. A new correction emits an additional quantity 0 item audit event at its actual correction time. Older parent-only correction audits cannot identify an immutable affected-item snapshot; their acquisition effect uses the corrected lot date and is explicitly incomplete. No historical per-item correction time or item membership is manufactured.
